GUIA RÁPIDO DE DEPLOY — SITE CASAMENTO

ESTADO ATUAL
- Frontend e backend são o mesmo projeto Next.js. As páginas e as APIs /api são publicadas juntas e usam a mesma URL.
- O banco é PostgreSQL, definido por DATABASE_URL. Nesta máquina ele está em localhost:5433, banco site_casamento; os arquivos locais ficam em .local-postgres-data (ignorado pelo Git). Isso não é produção nem um banco público.
- As migrations estão em prisma/migrations e o modelo em prisma/schema.prisma.
- Fotos locais ficam em .local-storage. Em hospedagem serverless, use Object Storage privado (R2, S3 ou compatível).

DEPLOY RECOMENDADO (Vercel + PostgreSQL gerenciado)
1. Envie o projeto para GitHub/GitLab e importe o repositório no Vercel (ou Render/Railway).
2. Crie um PostgreSQL gerenciado (Neon, Supabase, Railway, Render, RDS etc.). Copie a URL de conexão com SSL e coloque-a como DATABASE_URL no ambiente Production.
3. Crie um bucket privado para fotos e configure também:
   STORAGE_DRIVER=s3-compatible
   S3_ENDPOINT=https://...
   S3_REGION=...
   S3_BUCKET=...
   S3_ACCESS_KEY_ID=...
   S3_SECRET_ACCESS_KEY=...
   MAX_UPLOAD_BYTES=15728640
4. Antes do primeiro uso, rode uma vez contra o banco de produção:
   npm run db:deploy
   (equivale a npx prisma migrate deploy e não apaga dados.)
5. No host, use build `npm run build`. Se for necessário um comando de inicialização, use `npm run start`. No Vercel isso é automático.
6. Não rode `npm run db:seed` em produção; ele é apenas para demonstração e recria dados de exemplo.
7. Abra o domínio gerado e teste /, /planos, /app/login, uma rota /w/{token} e uma rota /api.

LINK DO CASAMENTO
- O formato é https://SEU-DOMINIO/w/{Wedding.publicId}.
- Use somente o publicId opaco gerado para o casamento (exemplo de demo: evt_demo_ana_joao_4f2h7k). Slugs como ana-e-joao não são credenciais públicas.
- O link exige status ativo e fica limitado a publicAccessStartsAt/publicAccessEndsAt. Depois do vencimento, o convidado perde acesso; fotos, convidados e pontuação continuam salvos para o painel.
- /evento/{token} existe apenas como redirecionamento legado para /w/{token}.

ADMINISTRAÇÃO
- A entrada da cerimonialista é /app/login, com e-mail e senha. Não há senha padrão nem cadastro público.
- A senha deve ser criada/provisionada pelo serviço seguro setAdminPassword; nunca coloque uma senha no código ou no Git.

BANCO DE DADOS E BACKUPS
- Em desenvolvimento, o PostgreSQL local só existe nesta máquina. Se ela for desligada ou o diretório for removido, os dados locais deixam de estar disponíveis.
- Em produção, o banco deve ser hospedado por você em um serviço gerenciado. Ative backups automáticos, SSL e monitore conexões. Guarde a DATABASE_URL apenas nas variáveis secretas do host.
- O bucket de fotos também deve ter backup/política de retenção; não dependa do armazenamento local do servidor.
