Quero iniciar um projeto web mobile-first voltado para casamentos, inspirado na ideia de um jogo de fotos para convidados.

O principal objetivo é permitir que convidados participem de desafios/missões fotográficas durante o casamento sem precisar instalar aplicativo.

A experiência deve ser extremamente simples:

QR Code → abrir o site → entrar no casamento → visualizar missões → tirar fotos → enviar → ganhar pontos → acompanhar ranking.

## Decisão de arquitetura

O projeto deve ser um Web App/PWA, e não um aplicativo nativo.

Motivos:

* convidados não devem precisar instalar aplicativo;
* deve funcionar diretamente pelo QR Code;
* deve funcionar tanto em iPhone quanto Android;
* prioridade máxima para Safari no iPhone;
* também deve funcionar corretamente no Chrome Android;
* o projeto será desenvolvido em Windows;
* deve ser pensado para conexão de internet ruim ou instável.

## Stack desejada

Preferencialmente utilizar:

Frontend:

* Next.js
* React
* TypeScript
* CSS responsivo/mobile-first

Backend:

* inicialmente pode utilizar API Routes do próprio Next.js;
* estruturar de forma que futuramente seja possível separar o backend.

Banco de dados:

* PostgreSQL

ORM:

* Prisma

Armazenamento de fotos:

* deixar a arquitetura preparada para Cloudflare R2, Amazon S3 ou outro Object Storage;
* inicialmente pode criar uma abstração de storage para facilitar desenvolvimento local.

PWA:

* Service Worker;
* cache da aplicação;
* funcionamento parcial offline.

## Conceito do sistema

Cada casamento será um evento.

Exemplo:

Casamento:
Ana & João

Cada casamento terá:

* nome dos noivos;
* data;
* código/token;
* QR Code próprio;
* convidados;
* missões;
* fotos;
* pontuação;
* ranking.

O QR Code deve direcionar para algo como:

/evento/abc123

O convidado não deve precisar criar uma conta tradicional com email e senha.

Inicialmente podemos identificar o convidado através de:

* nome;
* apelido;
* token armazenado no navegador.

Depois podemos evoluir isso.

## Fluxo do convidado

Ao acessar o QR Code:

1. Abrir página do casamento.

2. Mostrar algo como:

"Casamento de Ana & João"

"Entre no jogo de fotos"

3. Solicitar nome/apelido.

4. Entrar no jogo.

5. Tela principal deve mostrar:

* progresso das missões;
* pontuação;
* posição no ranking;
* missões disponíveis.

Exemplo:

Missão 7 de 20

"Tire uma foto dos noivos dançando"

+100 pontos

[TIRAR FOTO]

## Câmera

O sistema precisa permitir tirar fotos pelo celular.

Prioridade:

* usar a câmera traseira;
* funcionar bem em Safari/iPhone;
* funcionar em Chrome/Android.

Não quero depender inicialmente de uma câmera customizada complexa.

Pode utilizar input de arquivo com captura da câmera quando isso for mais confiável:

<input
type="file"
accept="image/*"
capture="environment"
/>

Depois da foto:

Mostrar preview.

Botões:

[Usar foto]

[Tirar novamente]

Somente após confirmação deve iniciar o upload.

## Qualidade das fotos

Evitar compressão excessiva.

Quero preservar boa qualidade.

A arquitetura deve permitir futuramente armazenar a foto original.

Não transformar tudo automaticamente em imagens de baixa resolução.

## Internet ruim / modo offline

Essa parte é MUITO importante.

O sistema deve assumir que a internet do casamento pode ser ruim ou cair frequentemente.

Se o usuário tirar uma foto e não houver internet:

NÃO perder a foto.

Guardar a foto temporariamente localmente, preferencialmente utilizando IndexedDB.

A foto deve possuir status como:

* pending
* uploading
* uploaded
* failed

Criar uma fila de uploads.

Exemplo:

Foto 1
✅ Enviada

Foto 2
⏳ Aguardando conexão

Foto 3
❌ Falha no envio
[Tentar novamente]

Quando houver conexão e o site estiver ativo, tentar enviar as fotos pendentes novamente.

NÃO depender exclusivamente de Background Sync, pois precisamos ter compatibilidade principalmente com Safari/iPhone.

## PWA

Quero transformar o projeto em uma PWA.

Mas o convidado NÃO será obrigado a instalar.

O fluxo principal continuará:

QR Code → navegador → jogar.

A PWA deve ajudar principalmente em:

* cache;
* carregamento;
* experiência mobile;
* alguma funcionalidade offline.

## Missões

Cada casamento terá diversas missões.

Exemplos:

"Tire uma foto dos noivos dançando"

"Tire uma selfie com alguém que você não conhecia"

"Fotografe alguém chorando"

"Tire uma foto com os padrinhos"

"Fotografe o primeiro beijo"

Cada missão terá:

* id;
* evento;
* título;
* descrição;
* pontos;
* ativa/inativa;
* ordem;
* quantidade máxima de envios, se necessário.

## Pontuação

Quando uma missão for concluída:

o convidado recebe os pontos daquela missão.

Exemplo:

Missão:
Foto com os noivos

Pontos:
100

Após enviar:

+100 pontos

O sistema deve evitar que o usuário fique enviando infinitas fotos para ganhar pontos repetidamente na mesma missão.

Inicialmente considerar uma missão concluída após um upload válido.

## Ranking

Criar ranking dos participantes.

Exemplo:

1. Mariana — 1.450 pts
2. Carlos — 1.200 pts
3. Fernando — 1.050 pts
4. Ana — 800 pts

Ranking atualizado conforme as missões forem concluídas.

## Fotos

Cada foto precisa estar relacionada a:

* casamento;
* convidado;
* missão;
* data/hora;
* URL da imagem;
* status.

Quero no futuro conseguir visualizar um álbum completo do casamento.

## Área administrativa

Criar arquitetura pensando em uma área administrativa.

Não precisa implementar tudo imediatamente.

Futuramente o administrador/noivos poderão:

* criar casamento;
* editar casamento;
* adicionar missão;
* editar missão;
* remover missão;
* definir pontuação;
* visualizar convidados;
* visualizar ranking;
* visualizar fotos;
* excluir foto;
* aprovar/reprovar fotos;
* gerar QR Code;
* baixar todas as fotos.

## Interface

Quero uma interface extremamente mobile-first.

Deve parecer mais um aplicativo do que um site tradicional.

Exemplo aproximado:

---

💍 Ana & João

MISSÃO 7/20

📸 Tire uma foto
dos noivos dançando

+100 pontos

[TIRAR FOTO]

🏆 320 pontos
4º lugar

Missões | Fotos | Ranking

---

Botões grandes.

Pouco texto.

Boa experiência com uma mão.

Evitar menus complexos.

Priorizar telas de celulares.

Depois adaptar para desktop.

## Segurança

Levar em consideração:

* validar tipos de arquivos;
* limitar tamanho dos uploads;
* evitar execução de arquivos maliciosos;
* gerar nomes únicos para imagens;
* não confiar em dados enviados pelo frontend;
* impedir alteração manual de pontuação pelo cliente;
* pontuação deve ser calculada no servidor;
* evitar que alguém consiga consultar eventos privados simplesmente alterando IDs.

Utilizar IDs seguros ou tokens para eventos.
